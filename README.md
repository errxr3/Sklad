# Склад зеркал

Складской учёт зеркал: каждое зеркало получает номер и этикетку со
штрихкодом. Сборщик печатает этикетку, клеит и сканирует — зеркало встаёт
на склад. При отгрузке его сканируют — оно списывается. Остаток считается сам.

Версия **0.1.0** — ядро. Полное задание: [docs/TZ.md](docs/TZ.md).

## Что умеет версия 0.1

- Вход по имени сотрудника и PIN-коду с выбором площадки.
- Справочник артикулов из `TOP.xlsx` (три листа, столбец A).
- «Сделал зеркало»: выбор артикула и количества, печать этикеток в PDF,
  приёмка сканом. Сборщик присваивается зеркалу навсегда.
- «Отгрузка»: скан списывает зеркало со склада.
- «Остатки»: артикул × площадка.
- Журнал движений: каждая смена статуса — отдельная запись, записи
  не удаляются и не правятся.
- Повторный скан и недопустимые переходы дают понятный отказ на экране.

## Что нужно для запуска

- Python 3.11 или новее (проверялось на 3.13).
- Больше ничего: база — файл SQLite, шрифты для этикеток лежат в репозитории.

## Установка

```bash
git clone <адрес репозитория> Sklad
cd Sklad

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Создайте файл `.env` (в репозиторий он не попадает):

```bash
cp .env.example .env
python -m app.cli gen-secret       # покажет строку SKLAD_SECRET_KEY=...
```

Полученную строку впишите в `.env` вместо `change-me-please`. Без своего
ключа приложение тоже работает, но при каждом перезапуске все сотрудники
выходят из системы.

## Подготовка данных

```bash
python -m app.cli init-db                      # создать базу и площадки
python -m app.cli import-articles TOP.xlsx     # загрузить справочник артикулов
python -m app.cli add-employee --name "Иванов Иван"
```

PIN-код показывается один раз при заведении сотрудника — запишите его.
В базе хранится только хеш. Если PIN не указать, он будет сгенерирован.

Для пробы, пока настоящего `TOP.xlsx` нет:

```bash
python -m app.cli seed-demo-articles     # 9 артикулов для проверки
python -m app.cli seed-test-workers      # два тестовых сборщика
```

## Запуск

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Сайт откроется по адресу `http://localhost:8000`.

Чтобы заходить с телефона, узнайте адрес компьютера в локальной сети
(`ip a` в Linux, `ipconfig` в Windows) и откройте `http://АДРЕС:8000` —
телефон и компьютер должны быть в одной сети Wi-Fi. На Windows может
потребоваться разрешить порт 8000 в брандмауэре.

## Команды управления

| Команда | Что делает |
|---|---|
| `python -m app.cli init-db` | создать базу и завести площадки |
| `python -m app.cli gen-secret` | сгенерировать ключ для `.env` |
| `python -m app.cli add-employee --name "..." [--pin 1234]` | завести сотрудника |
| `python -m app.cli set-pin --name "..." [--pin 1234]` | сменить PIN |
| `python -m app.cli list-employees` | показать сотрудников |
| `python -m app.cli import-articles TOP.xlsx` | загрузить справочник |
| `python -m app.cli seed-demo-articles` | артикулы для проверки |
| `python -m app.cli seed-test-workers` | два тестовых сборщика |
| `python -m app.cli stats` | сводка по базе |

## Как это работает

### Номер зеркала

Буквы группы плюс 7 цифр, например `Z0000123`. Буквы зависят от артикула:
`Zerkalo` и `bp_Zerkalo` — `Z`, `Alum` — `A`, `Ambient` — `AT`, остальное — `X`.
Счётчик цифр **один на все группы**: после `Z0000007` следующее зеркало
другой группы получит `A0000008`.

### Артикулы

Русская «х» и латинская «x» считаются одной буквой, лишние пробелы
убираются, регистр при сравнении не учитывается. Поэтому `Zerkalo 600х800`
и `ZERKALO  600x800` — один и тот же артикул, а не два.

### Статусы

```
Напечатано  →  На складе  →  Отгружено
```

Статусы «В пути» и «Списано» заведены в модели, но в версии 0.1 переходы
в них не используются. Любой другой переход запрещён, и экран объясняет,
почему: показывает текущий статус зеркала, кто и когда делал операцию.

### Площадки

Зеркало сканируется только на той площадке, где оно находится. Перемещений
между площадками в версии 0.1 нет — при попытке отсканировать чужое зеркало
экран скажет, на какой площадке оно лежит.

### Этикетка

58 × 40 мм, одна этикетка на страницу PDF — термопринтер печатает их подряд.
Ширина штриха Code 128 — 3 точки принтера с разрешением 203 dpi. Шрифты
DejaVu лежат в репозитории, чтобы кириллица печаталась одинаково на любом
компьютере. Образец: [docs/obrazec-etiketki.pdf](docs/obrazec-etiketki.pdf).

Если печать сорвалась, откройте PDF партии ещё раз по той же ссылке —
номера не изменятся. Новые номера выдаются только при новой печати.

## Проверка

```bash
pip install -r requirements-dev.txt
python -m pytest
```

80 тестов: нумерация, сравнение артикулов, импорт трёх листов, путь зеркала,
повторный скан, недопустимые переходы, остатки, журнал и сценарии через HTTP.
Штрихкод на этикетке растеризуется в 203 dpi и декодируется обратно —
проверяем, что сканер сможет его прочитать.

## Что не входит в версию 0.1

Связка с программой BLAGO OTGRUZKI, выгрузка в гугл-таблицу, перемещения
между площадками, инвентаризация.

## Переход на PostgreSQL

Вся работа с базой идёт через SQLAlchemy, отдельных SQL-запросов в коде нет.
Для перехода понадобится указать `SKLAD_DATABASE_URL` в `.env`, установить
драйвер `psycopg` и перенести данные. Правок в запросах не потребуется.

## Что не попадает в репозиторий

Файл базы (`data/`), `.env` с ключом, папка `secrets/` с PIN-кодами
тестовых сборщиков. Это прописано в `.gitignore`.
