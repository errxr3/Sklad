# История изменений

Формат: что изменилось и что сделать при обновлении.
Версии помечаются тегами в git.

## 0.2.0 — 10.10.2026

### Что появилось

- **Роли сотрудников.** Сборщик печатает этикетки и принимает на склад;
  грузчик отгружает; бригадир делает и то, и другое — принимает за
  сборщиком для проверки сборки; администратор может всё. Зеркало всё
  равно остаётся записанным на того сборщика, который его сделал:
  ни приёмка бригадиром, ни отгрузка грузчиком этого не меняют.
  На главной показываются только доступные роли кнопки, а при попытке
  зайти на чужой экран приложение объясняет, какая роль нужна.
- **Админ-панель** (`/admin`, только для роли администратора):
  - сводка: зеркала по статусам, остатки по площадкам, счётчики базы;
  - сотрудники: завести, сменить роль, сменить PIN, отключить и включить;
  - артикулы: добавить вручную, загрузить файлом .xlsx или .csv, отключить;
  - зеркала: поиск по номеру и артикулу, фильтры по статусу, площадке
    и сборщику, ручное исправление статуса;
  - журнал с фильтрами по номеру, сотруднику и действию.
- **Светлая и тёмная темы.** Переключаются кнопкой в шапке, выбор хранится
  в отдельной cookie на год — переживает выход из системы, страница сразу
  открывается в нужной теме. JavaScript для этого не нужен.
- **Остатки в виде исходной таблицы.** Строки разложены по разделам
  справочника («ПОЛОТНА», «АЛЮМИНИЙ», «БЕЗРАМНЫЕ», «БЕЗРАМНЫЕ КРУГЛЫЕ»
  и так далее) в том же порядке, что и в файле. Под каждым разделом итог,
  внизу общий. По умолчанию видны все артикулы, кнопка «Только с остатком»
  прячет пустые строки.
- **Загружен настоящий справочник**: 298 артикулов с трёх листов.
  Импорт научился разбирать реальный файл — пропускает шапку, строки
  итогов и заголовки разделов, а разделы и порядок строк запоминает.
- С главной убран заголовок «Что делаем?».

### Что сделать при обновлении

Ничего вручную делать не нужно: недостающие столбцы (`articles.section`,
`articles.sort_order`) дописываются при первом запуске сами.

Что стоит сделать после обновления:

1. Завести администратора, если его ещё нет:
   `python -m app.cli add-employee --name "Фамилия Имя" --role admin`
2. Раздать роли остальным — в админ-панели или командой:
   `python -m app.cli add-employee --name "..." --role loader`
   (роли: `assembler` — сборщик, `loader` — грузчик, `foreman` — бригадир,
   `admin` — администратор). Сотрудники из версии 0.1 остаются сборщиками.
3. Загрузить свежий справочник артикулов — в админ-панели или командой
   `python -m app.cli import-articles TOP.xlsx`. Повторная загрузка
   ничего не задваивает.
4. Если в базе остались демонстрационные артикулы из версии 0.1
   (`Zerkalo 600x800` и подобные), отключите их в админ-панели —
   тогда они пропадут из выбора при печати.

### Известные ограничения

- Колонки OZON, КГТ, СДЭК, WB Тверь, ТВ СГТ из исходной таблицы
  в остатках не воспроизведены: в файле они пустые, а в системе нет
  понятия направления отгрузки. Если нужно учитывать, куда уехало
  зеркало, это отдельная доработка — выбор направления при отгрузке.
- Остальные ограничения версии 0.1 в силе: перемещений между площадками
  нет, статусы «В пути» и «Списано» не используются.

## 0.1.0 — 10.10.2026

Первая рабочая версия: ядро складского учёта.

### Что появилось

- **Вход** по имени сотрудника и PIN-коду с выбором площадки
  (Коминтерна, Учительская). PIN хранится хешем PBKDF2-SHA256.
- **Справочник артикулов** с загрузкой из `TOP.xlsx`: читаются все листы,
  столбец A, пропускаются заголовки и пустые строки. Русская «х»
  приравнена к латинской «x», лишние пробелы убираются, регистр при
  сравнении не учитывается.
- **«Сделал зеркало»**: поиск артикула, выбор количества, печать этикеток
  в PDF, приёмка сканом. Сборщик присваивается зеркалу навсегда.
- **Нумерация**: буквы группы плюс 7 цифр, счётчик общий на все группы
  (`Zerkalo`, `bp_Zerkalo` — `Z`, `Alum` — `A`, `Ambient` — `AT`,
  остальное — `X`).
- **Этикетка** 58 × 40 мм в PDF: чёрная шапка «СКЛАД» с площадкой, артикул
  крупно, штрихкод Code 128 с шириной штриха 3 точки при 203 dpi, номер
  цифрами, внизу сборщик и дата. Одна этикетка на страницу.
- **«Отгрузка»**: скан списывает зеркало со склада.
- **«Остатки»**: артикул × площадка, считаются зеркала «На складе».
- **Журнал движений**: каждая смена статуса — отдельная запись. Кода,
  который правит или удаляет записи, в приложении нет.
- **Понятные отказы**: повторный скан, недопустимый переход, неизвестный
  номер, нечитаемый код, чужая площадка — экран объясняет, что не так,
  и показывает, кто и когда делал операцию.
- **Карточка зеркала** с полной историей и повторной печатью партии.
- Вёрстка под телефон: крупные кнопки, поле скана всегда в фокусе.
- Команды управления: `init-db`, `gen-secret`, `add-employee`, `set-pin`,
  `list-employees`, `import-articles`, `seed-demo-articles`,
  `seed-test-workers`, `stats`.
- 80 тестов, включая проверку читаемости штрихкода: этикетка
  растеризуется в 203 dpi и штрихкод декодируется обратно.

### Что исправлено по ходу работы

- **Список сканов переполнял cookie.** Он хранился в cookie-сессии; тексты
  отказов длинные, и за десяток зеркал cookie перерастала предел 4096 байт.
  Браузер отбрасывал её целиком вместе со входом — сообщения переставали
  появляться, а сборщика выкидывало на страницу входа посреди смены.
  Теперь список лежит в памяти сервера, в cookie остаётся 191 байт.
- **Кнопки количества не печатали этикетки.** У кнопок-пресетов и у поля
  «другое количество» было одно имя, браузер отправлял оба значения,
  и до сервера доходила пустая строка. Теперь у поля своё имя.

### Что сделать при обновлении

Это первая версия — обновляться не с чего. Порядок первой установки
описан в [README.md](README.md). Коротко:

```bash
pip install -r requirements.txt
cp .env.example .env
python -m app.cli gen-secret        # строку вписать в .env
python -m app.cli init-db
python -m app.cli import-articles TOP.xlsx
python -m app.cli add-employee --name "Фамилия Имя"
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Известные ограничения

- Перемещений между площадками нет: зеркало сканируется там, где лежит.
- Статусы «В пути» и «Списано» заведены в модели, но не используются.
- Нет связки с BLAGO OTGRUZKI, выгрузки в гугл-таблицу и инвентаризации —
  они и не входили в версию 0.1.
- Справочник артикулов нужно загрузить из настоящего `TOP.xlsx`:
  команда `seed-demo-articles` заводит временный набор для проверки.
